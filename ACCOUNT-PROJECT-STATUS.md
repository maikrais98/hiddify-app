# Luma: цель кабинета и результат этапа U3

Дата: 27 октября 2026. Назначение ветки `feat/luma-u3-account-debug` — отдельная проверка аккаунта на Mac и физическом iPhone. Это исходники тестовой интеграции, не выпуск приложения. Основная ветка, установленная рабочая версия и production VPN остаются самостоятельным направлением.

## Что хотим получить

Пользователь входит в Luma по подтверждённой почте или Telegram и получает доступ к своей существующей VPN-подписке. Сервер кабинета хранит аккаунты, подтверждённые способы входа, сессии и права доступа. Remnawave остаётся источником параметров подписки. Создание аккаунта Luma само по себе не создаёт новую VPN-подписку.

Следующие возможности:

- Показать статус подписки, срок, трафик и разрешённые действия; получить конфигурацию через проверенный доступ.
- Сохранить существующий ручной импорт подписок, локальный email и аватар.
- Добавить учёт зарегистрированных устройств и общий настраиваемый лимит. Пример «пять устройств» означает места регистрации, не пять одновременных соединений.
- Добавить семейные приглашения: родственники входят собственными аккаунтами и используют общий доступ в пределах лимита.
- В дальнейшем обслуживать аккаунт Luma и веб-кабинет одним сервером.

Для первого семейного этапа пользователь согласовал: исключение участника закрывает кабинет и новые загрузки. Мгновенный отзыв уже сохранённой VPN-конфигурации этим действием не обещается.

## Что уже сделал Codex

### U0–U2: аудит, изолированный прототип и контракты

Изучил исходники Luma и кандидат Minishop Core, подготовил отдельный лабораторный прототип на синтетических данных, контракты API/хранения/отзыва и решения по сессиям. Minishop использован как проверяемая основа прототипа: полноценный магазин с платежами, рассылками и синхронизацией production не запускался. U0 не был аудитом реальных пользователей рабочей панели.

### U3: сервер и постоянное хранение

Реализовал email-вход с одноразовым кодом и привязкой к начавшему вход клиенту (PKCE), постоянные сессии, rotation refresh, logout, повторное подтверждение чувствительного действия и отзыв одной/всех сессий. Добавил HTTP API по готовым операциям U3, проверки прав, разделение аккаунтов, пагинацию и безопасные ошибки.

Хранение сначала проверялось на файловой SQLite по согласованной альтернативе, затем отдельно проверено на настоящем тестовом PostgreSQL. По отдельным разрешениям развернул на Гермесе изолированные PostgreSQL и закрытый HTTP-сервис на выделенном тестовом хранилище. Для тестовой БД включён разрешённый автозапуск; автозапуск HTTP-сервиса этим этапом не включался. Настоящие пользователи, SMTP, Telegram и рабочая база VPN не подключались.

Серверные результаты относятся к отдельному backend-проекту и его отчётам. Этот Flutter branch не содержит его базы, ключей, deployment state или полной реализации backend. Доступность службы на момент будущего запуска нужно проверять отдельно.

### U3: клиент Luma в этой ветке

- Добавил отдельный сетевой клиент без общего retry/proxy fallback: одноразовый refresh автоматически не повторяется.
- Реализовал вход, восстановление сессии, список сессий, logout, reauth и отзыв одной/всех сессий; добавил защиту от запоздавших ответов после выхода и смены состояния.
- Подготовил iOS Keychain-мост: refresh и идентификаторы хранятся отдельно от VPN; access остаётся в памяти. При неопределённом результате rotation требуется новый вход.
- Добавил debug-экран и отдельную точку запуска `lib/main_account_lab.dart`, без обычной инициализации core/telemetry/VPN. Переход из профиля доступен только за debug-флагом.
- Выделил Debug bundle ID, extension ID и App Group с суффиксом `.u3debug`, имя `Luma U3 Lab`, ручную подпись и отдельное разрешение локальной сети. Release/Profile настройки сохранены.
- Подготовил локальный TLS relay для маршрута iPhone → Mac → существующий SSH → закрытый API; публичный endpoint не создавался.
- Подготовил [инструкцию для Mac](docs/u3-client/MAC.md), тесты и журнал [выполненной работы](docs/u3-client/history.md).

Конкретные SSH-адреса, пути закрытого mailbox, учётные данные и локальные сертификаты в эту ветку не включаются. GitHub содержит исходники; это не делает тестовую БД или API публичными.

## Что проверено и что ещё нет

До подготовки публикации прошли 47 локальных Flutter-тестов, 7 Python-проверок TLS relay и сохранности Release configuration, целевой анализ Dart без замечаний. Отдельный клиентский smoke через настоящий тестовый API проверил вход, /me/sessions, восстановление с refresh, reauth, revoke-all и отказ сервера для отозванного refresh. Эти тесты использовали синтетические записи; созданная smoke сессия отозвана.

Перед публикацией добавлены две проверки обязательных локальных настроек live smoke и защиты от подстановки SSH options/remote commands. Итоговый повторный прогон: **49 Flutter-тестов passed**, live smoke по умолчанию skipped; **7 Python-тестов passed**, анализ Dart без замечаний. Обычный набор не подключается к Гермесу: live smoke требует явного включения и локальных настроек.

**Пока не проверены:** Xcode build на Mac пользователя, подходящие отдельные development profiles, подписанные entitlements, настоящий Keychain и закрытое соединение физического iPhone. Пользователь согласовал эти проверки на своём Mac вместо отсутствующего здесь Xcode. До них не заявляем, что приложение проверено на iPhone.
